# 坑

按"你大概率先撞上哪个"的顺序排的踩坑清单。每一条都先给症状 —— 可以直接对着你眼下的现象扫。

这里大部分行为是**故意静默**的：框架不认识的东西直接忽略，而不是抛异常。如果症状对不上这张清单，打开严格模式重跑一次：

```bash
# Windows
$env:QT_DEBUG_STRICT = "1"
# macOS / Linux
QT_DEBUG_STRICT=1 ./build/app
```

严格模式会把未知控件类型、未知属性、未知 `patch()` method 以警告打到 stderr。普通构建下它们悄无声息地被丢掉。

## 控件越加越多，开始空白或闪烁

**症状。** 页面短的时候一切正常。页面变长 —— 或者列表、表格、条件分支一变数量 —— 部分界面就空白、闪烁，或者你没碰过的控件丢了焦点。

**原因。** 这个节点没有 `id`。没有 id 的节点会拿到按位置推导的隐式 id（`_p<path>`），而这个路径只保证**帧内**稳定。前面插入或删掉一个兄弟节点，后面所有匿名节点都会换 id —— 于是下一帧不是复用而是重建，旧控件从布局里脱落。

**修法。** 动态容器（列表行、表格行、树节点、条件分支）里的每个孩子都给显式 `id`。id 就是控件跨帧的身份；换 id 等于换控件。完整机制见 [diff 引擎](/zh/advanced/diff-engine.md)。

## 用 `patch()` 改过的控件，下一帧又变回去了

**症状。** 你调 `patch(['op'=>'call', 'id'=>'t', 'method'=>'appendRows', ...])`，行确实出现了 —— 然后下一次 `render()` 又把旧内容放了回去。

**原因。** `patch()` 是命令式旁路：它改的是控件，不是树。树仍然是唯一事实来源，diff 一看"树说是 X、控件说是 Y"，就把树重新按回去。

**修法。** 这不是要绕开的 bug，这就是契约。要么同时更新自己的状态**和**树，让下一帧两边对上；要么每帧都继续走这个命令式调用，把它当快路径。桥接**会自动作废**这次调用碰过的属性的 diff 签名，所以下一次 `render()` 会以树为准重新同步，而不是相信一个过期的签名。**`forgetProps()` 不需要你自己调** —— 它是桥内部的事。

## 某个控件类型或属性好像完全没作用

**症状。** 加了个属性或一种控件，程序照样跑，但界面毫无变化。也没有报错。

**原因。** 未知控件类型、未知属性、未知 `patch()` method 都是**静默忽略**的。这是有意的：一个属性拼错，不该整个应用陪葬。

**修法。** 用 `QT_DEBUG_STRICT=1` 跑，看 stderr。再对着[常用属性](/zh/guide/properties.md)核名字 —— 最常见的两种是：在叶子控件上用了容器的属性，或者该读 `text` 的控件你写了 `value`。

## 大表格每帧都在重建

**症状。** CPU 随行数上涨。五千行的表格什么都没变，滚动起来也很重。

**原因。** `rows` / `nodes` 是结构字段：签名每帧都要算，签名一变就重建控件。数据量大时这一项就能吃掉整个预算。

**修法。** 别重建，改成增量追加：

```php
$app->patch([[ 'op' => 'call', 'id' => 't', 'method' => 'appendRows', 'args' => [$newRows] ]]);
```

记得上面那条旁路规则：树也得对上，否则下一帧会把它撤销。详见[性能](/zh/advanced/performance.md)。

## 托盘图标把无头运行卡死

**症状。** `--selftest` 或 CI 跑着跑着永远挂住，没有窗口。

**原因。** 没有系统托盘时，`qt_window_notify()` 会退化成**模态对话框**，一直阻塞到有人点它。无头环境里没有人。

**修法。** 无头模式下跳过通知（`$app->headless(true)` 会让 `show()` / `notify()` 变成空操作），或者自己加判断：

```php
if (!$app->headless()) {
    $app->notify('构建完成');
}
```

## 命名空间文件里桥接函数"未定义"

**症状。** `\qt_...()` 在 `main` 里好好的，换个带 `namespace` 的文件调同一个函数就解析不到。

**原因。** 桥接函数是全局函数。在命名空间里，非全限定调用会先在当前命名空间找。

**修法。** 一律带前导反斜杠调用：`\qt_window_focus($w)`。

## 加了个桥接函数，`qtphp lint` 就报了错

**症状。** 加完 `php_*` 函数，`qtphp lint` 报契约不一致。

**原因。** 每个桥接 API 必须**两处**同时存在：`php-src/qt.stub.php` 里的 stub（函数体必须为空 `{}`），以及 `cpp-src/*.cc` 里带 `php_` 前缀的实现。lint 就是拿这两边做比对。

**修法。** 先加 stub 声明，再加 C++ 实现。如果接着 PHP 侧单测报"函数不存在"，说明你还漏了 `src/FakeBridge.php` 里同签名的桩。四件套步骤见[手写桥接](/zh/advanced/bridge.md)。

## 窗口关了，进程还活着

**症状。** 你关掉窗口，任务管理器里进程还在。

**原因。** 托盘应用会设 `setQuitOnLastWindowClosed(false)`，让关窗口不等于退出 —— 那循环就得靠别的方式知道该停。

**修法。** 主循环条件用 `is_alive`（你自己的标志），不要用 `is_open`。用户真的要求退出时（托盘"退出"项、菜单动作）把标志置掉，循环自然结束。

## 第二个窗口永远不刷新

**症状。** 两个 `QtApp` 实例，第一个窗口正常更新，第二个冻住 —— 或者两个轮流卡。

**原因。** `run()` 只泵自己窗口的事件。两个独立的 `run()` 就是互相饿死。

**修法。** 自己推帧：每个 tick 里轮流对两个 app 各调一次 `runFrames(1)`。见[多窗口、托盘与定时器](/zh/guide/menus-tray-timers.md)。

## 编译产物找不到 Qt 的 DLL 或插件

**症状。** exe 编出来了，但一启动就退出，或者起来了却没有可用的窗口，抱怨找不到 `qwindows.dll` 或平台插件。

**原因。** Qt 运行时 —— 那堆 DLL 加上 `platforms/` 插件目录 —— 没放在可执行文件旁边。

**修法。** 用 `qtphp run`（会自己设好路径）或 `qtphp package`（会拷运行时并写 `qt.conf`）。手动构建时，把 `qwindows`、`qoffscreen`、`qminimal` 部署到 `build/platforms/`。Windows 上 `--no-console` 才是产出 GUI 子系统的方式。

## 打包之后 HTTPS 全失败

**症状。** 开发时一切正常；一打包，`qt_http_request()` 发的每个 HTTPS 请求都报错。

**原因。** 打包时跳过了 `tls` / `networkinformation` 插件。

**修法。** **不要**跳过它们。只要应用联网，这两个就不是可选项 —— 省了一点体积，废掉全部 HTTPS。`--no-opengl-sw` 才是安全的减重；它只去掉 20 MB 的软件光栅化器。

## 本地能编译，CI 机器上不行

**症状。** `tpc` 拒收 `project.yml`，或者 MSVC 不认某个编译选项。

**原因。** nano 对 C++ 标准卡得很死，MSVC 上 Qt 又需要显式开关。

**修法。** 示例/应用的 `project.yml` 用 **`c++17`**（根目录的库配置用 `c++20`）。MSVC 上 Qt 需要 `/Zc:__cplusplus /permissive-`。Windows 上 WebView2 需要 `third_party/webview2/x64/WebView2Loader.dll.lib` 在位 —— 新克隆少了它会 `LNK1181`（仓库 `.gitignore` 是刻意保住这个文件的）。
